# Pair programming / mob programming?

> Don't just talk results — talk **impact on the team**.

## Strong answer

I see pair programming as a **tool rather than a default approach**.

It's especially valuable for **complex problems, critical code paths, or onboarding new team members**.

It helps improve code quality, encourages **knowledge sharing**, and reduces **silos** across the team.

In my experience, it also **speeds up problem-solving** in uncertain areas and leads to better design decisions through real-time collaboration.

That said, I use it **selectively** — some tasks are more efficient to handle asynchronously — so I try to balance collaboration with individual focus.

## Key framing

Pair = tool. Pick when value > cost. Avoid sounding dogmatic.
