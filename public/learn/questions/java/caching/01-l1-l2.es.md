# L1 vs L2 cache

> L1 = más cercano, más rápido, in-process. L2 = distribuido, compartido entre instancias.

## L1 — cache in-process

- Vive **dentro del proceso** (heap del JVM).
- Ultra rápido (nanosegundos).
- **No compartido** entre instancias.
- Se pierde al reiniciar.

Herramientas: `Caffeine`, `Guava Cache`, Hibernate Session cache.

## L2 — cache distribuido

- **Externo** al proceso (servicio separado).
- Más lento que L1 (milisegundos — pero mucho más rápido que la DB).
- **Compartido** entre instancias.
- Persiste (según configuración).

Herramientas: **Redis**, Memcached, Hazelcast.

## Trade-offs

| | L1 | L2 |
|---|---|---|
| Velocidad | ⚡ ns | ms |
| Compartido | ❌ | ✅ |
| Sobrevive restart | ❌ | ✅ (Redis con persistencia) |
| Consistencia entre pods | ❌ (cada uno el suyo) | ✅ |
| Presión de memoria | Por pod | Centralizada |

## Otros contextos (para que no te tomen desprevenido)

- **Hibernate L1/L2** — L1 es el Session cache (siempre activo), L2 es un cache compartido opcional (Ehcache, Hazelcast).
- **CPU L1/L2** — caches de hardware en el chip; otra conversación.
